4. CONTRACT SKELETON DEFINITIONS
--------------------------------------------------------------------------------

4.1 EVIDENCE RECORD v1.0.0
--------------------------
Ownership: WHAT WAS OBSERVED
Factual and derived observations available to the Sound Engineer before
engineering judgement and tone design decisions take place. Strictly observations:
no engineering prescriptions or gear choices.

Public Shape:
export interface EvidenceRecord {
  readonly contractVersion: "1.0.0" | string;
  readonly evidenceId: EvidenceId; // e.g. "evi_..."
  readonly runId: RunId;
  readonly stream: ExecutionStream;
  readonly createdAt: string;
  readonly sources: ReadonlyArray<ArtifactReference>;
  readonly musicalContext?: ObservedMusicalContext;
  readonly acousticCharacteristics?: ObservedAcousticCharacteristics;
  readonly confidence: number;
  readonly uncertainties: ReadonlyArray<string>;
  readonly provenance?: EvidenceProvenance;
}


4.2 ENGINEERING DECISION RECORD v1.0.0
--------------------------------------
Ownership: WHAT THE SOUND ENGINEER DECIDED + WHY
Sound-engineering judgement about WHAT should be done and WHY. Expresses musical
and acoustic intent, constraints, and trade-offs. Strictly decoupled from target
platform implementation details.

Public Shape:
export interface EngineeringDecisionRecord {
  readonly contractVersion: "1.0.0" | string;
  readonly decisionRecordId: DecisionRecordId; // e.g. "edr_..."
  readonly runId: RunId;
  readonly stream: ExecutionStream;
  readonly createdAt: string;
  readonly evidenceReference: ArtifactReference;
  readonly overallObjective: string;
  readonly decisions: ReadonlyArray<EngineeringDecisionItem>;
  readonly confidence: number;
}

export interface EngineeringDecisionItem {
  readonly decisionId: string;
  readonly category: EngineeringDecisionCategory | string;
  readonly purpose: string;
  readonly intent: string;
  readonly rationale: string;
  readonly constraints: ReadonlyArray<string>;
  readonly tradeOffs?: ReadonlyArray<string>;
  readonly dependencies?: ReadonlyArray<string>;
}


4.3 SEMANTIC TONE DESIGN v1.0.0
-------------------------------
Ownership: PLATFORM-INDEPENDENT EXECUTABLE INTENT

  readonly decisionRecordReference: ArtifactReference;

  readonly stages: ReadonlyArray<SemanticProcessingStage>;
  readonly constraints: ReadonlyArray<string>;
}

export interface SemanticProcessingStage {
  readonly stageId: string;
  readonly stageIndex: number;
  readonly role: string;
  readonly designIntent: string;
  readonly frequencyStrategy?: SemanticFrequencyStrategy;
  readonly gainStrategy?: SemanticGainStrategy;
  readonly dynamicsStrategy?: SemanticDynamicsStrategy;
  readonly cabinetStrategy?: SemanticCabinetStrategy;
  readonly captureStrategy?: SemanticCaptureStrategy;
  readonly ambienceStrategy?: SemanticAmbienceStrategy;

}


4.4 VALIDATION REPORT v1.0.0
----------------------------
Ownership: WHETHER THE CONTRACT IS COHERENT, COMPLETE, AND EXECUTABLE
Deterministic assessment of contract quality, coherence, and executability.
Strictly reports problems without repairing, mutating, or redesigning the
upstream contract.

Public Shape:
export interface ValidationReport {
  readonly contractVersion: "1.0.0" | string;
  readonly reportId: ValidationReportId; // e.g. "val_..."
  readonly runId: RunId;
  readonly stream: ExecutionStream;
  readonly createdAt: string;
  readonly targetArtifact: ArtifactReference;
  readonly overallStatus: "PASS" | "WARN" | "FAIL";
  readonly isExecutable: boolean;
  readonly summaryCounts: ValidationSummaryCounts;
  readonly findings: ReadonlyArray<ValidationFinding>;
}

export interface ValidationFinding {
  readonly findingId: string;
  readonly severity: "ERROR" | "WARNING" | "INFO";
  readonly ruleCode: string;
  readonly message: string;
  readonly location?: FindingLocation;
  readonly context?: Readonly<Record<string, unknown>>;
}


4.5 PLATFORM TRANSLATION PLAN v1.0.0
------------------------------------
Ownership: HOW A SPECIFIC TARGET PLATFORM WILL REALISE THE INTENT
Maps a validated SemanticToneDesign into concrete, target-platform-specific devices,
routing configurations, and parameter recipes. Explicitly permitted to contain
platform-specific implementation data, while remaining capable of targeting
multiple distinct platforms (e.g. AT5, Quad Cortex, Helix).

Public Shape:
export interface PlatformTranslationPlan {

  readonly planId: PlanId; // e.g. "ptp_..."
  readonly runId: RunId;
  readonly stream: ExecutionStream;
  readonly createdAt: string;
  readonly semanticDesignReference: ArtifactReference;
  readonly validationReportReference?: ArtifactReference;
  readonly targetPlatform: TargetPlatformIdentity;
  readonly translationDecisions: ReadonlyArray<PlatformTranslationItem>;
  readonly substitutions: ReadonlyArray<PlatformSubstitution>;
  readonly unresolvedMappings: ReadonlyArray<UnresolvedMapping>;
  readonly capabilityLimitations: ReadonlyArray<string>;
  readonly warnings: ReadonlyArray<string>;
  readonly translationConfidence: number;
}


5. OWNERSHIP BOUNDARIES & ARCHITECTURAL SEPARATION
--------------------------------------------------------------------------------
The responsibilities are strictly separated across 5 layers:

  EvidenceRecord:
    - Belongs: Factual musical context, extracted frequency envelope, dynamic
      range, observed saturation texture, ambient characteristics, uncertainty.
    - Excluded: What gear should be used, parameter adjustments, tone shaping
      recommendations.

  EngineeringDecisionRecord:
    - Belongs: Sound-engineering judgement, high-level objectives, decisions,
      acoustic purpose, constraints, trade-offs, and rationale.
    - Excluded: Specific hardware/software models, GUIDs, XML, concrete platform
      parameters.

  SemanticToneDesign:
    - Belongs: Platform-independent executable signal chain architecture,
      processing stage roles, frequency cutoff strategies, headroom profiles,
      transducer roles, cabinet acoustic requirements.
    - Excluded: AT5 gear IDs, vendor model names, XML presets, VIR coordinates.

  ValidationReport:
    - Belongs: Structural and acoustic coherence assessments, error/warning findings,
      location references, execution readiness determination.
    - Excluded: Automatic repair, rewriting decisions, mutating stage properties.

  PlatformTranslationPlan:
    - Belongs: Target platform identification (AT5, Quad Cortex, Helix), concrete
      model mapping, parameter recipes, substitution tracking, unresolved items.
    - Excluded: Generic sound engineering judgement (inherited from upstream).


6. ARTIFACT LINEAGE
--------------------------------------------------------------------------------
Artifacts connect strictly using Phase 1B.1 `ArtifactReference` instances,
avoiding recursive payload bloat and mutation leaks:

  InputSnapshot (from Phase 1A)
        │
        ▼ (referenced in sources array)
  EvidenceRecord (evi_...)
        │
        ▼ (referenced in evidenceReference)
  EngineeringDecisionRecord (edr_...)
        │
        ▼ (referenced in decisionRecordReference)
  SemanticToneDesign (std_...)
        │
        ▼ (referenced in targetArtifact)
  ValidationReport (val_...)
        │
        ▼ (referenced in semanticDesignReference & validationReportReference)
  PlatformTranslationPlan (ptp_...)

8. IMMUTABILITY & SIDE EFFECTS
--------------------------------------------------------------------------------
- All artifacts are constructed using defensive cloning (`defensiveClone`) on
  incoming arrays and nested objects.
- All returned objects, arrays, and sub-structures are recursively frozen via
  `deepFreeze`.
- Verified by automated unit tests 14 & 15: Neither caller-side array manipulation
  nor consumer-side property modification can alter an existing contract instance.
- Side effects: None. Contract instantiation is pure in-memory calculation with
  zero I/O, zero network, zero Firestore, and zero Gemini API calls. No global
  state or module registries exist.
