1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
Phase 1B.3 establishes the RunTrace and RunTraceRecorder observability framework
for the Sound Engineer pipeline.

A RunTrace represents the complete chronological execution history of an
individual Sound Engineer run:
  - What run and stream this was (runId, stream).
  - Which layers participated and in what explicit execution sequence.
  - What artifact each layer consumed and produced (lineage).
  - What status each layer reached (including non-fatal WARNING and SKIPPED).
  - How long each layer took (wall-clock vs. summed duration).
  - What diagnostics were logged, attributed to layer and checkpoint.
  - Overall derived lifecycle status.

Crucially, RunTrace is an OBSERVABILITY ARTIFACT. It does not own execution,
does not call Gemini, does not execute layers, and does not alter CURRENT TT.
CURRENT production remains 100% protected and unchanged.

All 31 focused unit tests and the 290-test full regression suite passed with
zero failures. The production bundle compiled in 2.30s.

4. RUNTRACE CONTRACT
--------------------------------------------------------------------------------
The public RunTrace contract defines a complete, versioned snapshot:

export interface RunTrace {
  readonly contractVersion: "1.0.0" | string;
  readonly traceId: TraceId; // e.g. "trc_..."
  readonly runId: RunId;
  readonly stream: ExecutionStream; // CURRENT | SHADOW | DEV
  readonly createdAt: string;
  readonly updatedAt: string;
  readonly status: TraceLifecycleStatus;
  readonly checkpointCount: number;
  readonly checkpoints: ReadonlyArray<TraceCheckpointEntry>;
  readonly diagnostics: TraceDiagnosticSummary;
  readonly timing: TraceTimingSummary;
  readonly lineage: ReadonlyArray<TraceLineageEntry>;
}

5. RECORDER / BUILDER API
--------------------------------------------------------------------------------
The `RunTraceRecorder` encapsulates all trace mutation within an isolated,
strongly-typed recorder instance:

Class: RunTraceRecorder
  - recordCheckpoint(checkpoint: CheckpointEnvelope<unknown>): TraceCheckpointEntry
      Appends a checkpoint. Rejects invalid envelopes, cross-run checkpoints,
      cross-stream checkpoints, and duplicate checkpoint IDs.
  - getTraceSnapshot(): RunTrace
      Returns a deeply frozen, immutable RunTrace snapshot.
  - getCheckpoints(): ReadonlyArray<CheckpointEnvelope<unknown>>
      Returns all recorded checkpoints in chronological sequence.
  - getCheckpointsByLayer(layer: LayerIdentity): ReadonlyArray<CheckpointEnvelope<unknown>>
      Filters checkpoints by layer (supports retries/iterations).
  - getCheckpointById(checkpointId: string): CheckpointEnvelope<unknown> | undefined
      Finds a checkpoint by ID.
  - getDiagnostics(): ReadonlyArray<TraceDiagnosticEntry>
      Returns all diagnostics across all layers with sequence attribution.
  - getArtifactLineage(): ReadonlyArray<TraceLineageEntry>
      Returns the lineage entries across the trace.
  - getEntryCount(): number
  - getStatus(): TraceLifecycleStatus

Factory:
  createRunTraceRecorder({ runId, stream, traceId?, createdAt? }): RunTraceRecorder


6. ORDERING MODEL
--------------------------------------------------------------------------------
The architecture explicitly distinguishes EXECUTION SEQUENCE ORDER from
COMPLETION TIMESTAMP:
  - Each recorded checkpoint is assigned an explicit, 0-indexed monotonic
    `sequenceIndex` reflecting when it was scheduled or recorded.
  - Asynchronous completion timing does not reorder checkpoints. An earlier
    layer that took 50ms will always precede a subsequent layer that finished
    in 10ms.
  - Verified by automated unit test 11.


7. TRACE STATUS DERIVATION & PRECEDENCE RULES
--------------------------------------------------------------------------------
The overall trace lifecycle status is passively derived via `deriveTraceStatus()`
according to the following strict precedence:

  1. FAILED:
     If ANY checkpoint has status === "failed", the run trace status is FAILED.
  2. CANCELLED:
     If ANY checkpoint was cancelled and none failed, status is CANCELLED.
  3. RUNNING:
     If any checkpoint is actively "running", status is RUNNING.
  4. WARNING:
     If all checkpoints have reached terminal states and at least one is WARNING,
     status is WARNING (crucially, WARNING !== FAILED).
  5. COMPLETED:
     If all checkpoints are terminal (completed or skipped) and no errors/warnings occurred.
  6. PENDING:
     If no checkpoints exist or all recorded checkpoints are pending.
  7. RUNNING:
     Default when intermediate mixed states exist (e.g. some completed, some pending).

Rules Verified by Tests:
  - Test 12: An ENGINEERING checkpoint with status "warning" yields trace status WARNING,
    not FAILED.
  - Test 15: A SKIPPED checkpoint counts as terminal and does not fail the trace.


8. DIAGNOSTIC AGGREGATION
--------------------------------------------------------------------------------
- Diagnostics are aggregated across all recorded checkpoints without flattening.
- Each `TraceDiagnosticEntry` retains:
    - The underlying structured `CheckpointDiagnostic` (severity, code, message, source, context).
    - Originating `layer` (e.g. ENGINEERING).
    - Originating `checkpointId`.
    - `sequenceIndex`.
- Summary counters provide instant counts for `totalCount`, `errorCount`,
  `warningCount`, and `infoCount`.


9. TIMING AGGREGATION
--------------------------------------------------------------------------------
- `startedAt`: Earliest `startedAt` timestamp across recorded checkpoints.
- `completedAt`: Latest `completedAt` timestamp across recorded checkpoints
  (only set if all executed checkpoints are terminal).
- `wallClockDurationMs`: Elapsed wall-clock time between earliest start and latest completion.
- `summedLayerDurationMs`: Arithmetic sum of individual checkpoint `durationMs` values.
- Pending checkpoints have no fabricated timing fields.


10. ARTIFACT LINEAGE
--------------------------------------------------------------------------------
Lineage is inspectable across the pipeline through `ArtifactReference`:
  - Each `TraceLineageEntry` records consumed `inputs` and produced `output`.
  - Artifact payloads are NOT duplicated for lineage tracking.
  - Enables consumers to follow the exact pipeline progression:
      InputSnapshot -> EvidenceRecord -> EngineeringDecisionRecord ->
      SemanticToneDesign -> ValidationReport -> PlatformTranslationPlan.


11. IMMUTABILITY STRATEGY
--------------------------------------------------------------------------------
- Controlled Ingestion: New checkpoints can only be added through `recordCheckpoint()`.
- Public Protection: `getTraceSnapshot()`, `getCheckpoints()`, and query methods return
  recursively frozen objects and arrays via `deepFreeze()`.
- Tamper Resistance:
    - Mutating arrays returned from query methods throws `TypeError` in strict mode.
    - Mutating properties on `RunTrace` throws `TypeError`.
    - Internal recorder state is completely decoupled from returned snapshots.


12. STALE / INVALID UPDATE PROTECTION
--------------------------------------------------------------------------------
The recorder strictly rejects:
  1. Cross-run contamination: Checkpoint with mismatched `runId` throws Error (Test 6).
  2. Cross-stream contamination: Checkpoint with mismatched `stream` throws Error (Test 7).
  3. Duplicate identity: Re-recording an existing `checkpointId` throws Error (Test 8 & 24).
  4. Invalid envelopes: Malformed checkpoints are rejected immediately.


13. SIDE EFFECTS & PRODUCTION PROTECTION
--------------------------------------------------------------------------------
- Side Effects: ZERO. Purely in-memory operations. No filesystem, no localStorage,
  no Firestore, and no Gemini API calls.
- Module Scope: No global mutable registries exist (`allTraces = []` does not exist).
  Each trace is owned entirely by its recorder instance.
- Production Protection: CURRENT tone translation (`translateTone`, `buildToneProfile`,
  gear resolution, VIR calibration, `.at5p` export) remains completely untouched
  and does not route through RunTrace.
